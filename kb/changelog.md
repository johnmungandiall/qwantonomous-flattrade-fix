# Changelog — notable changes, newest first.

One line per change that future-you or the agent should know about.

## Unreleased
- **mStock brought up to the Flattrade square-off standard + IOC validity (2026-10-27).** `broker/mstock/api/order_api.py#close_all_positions` no longer reports a false success: it reads the book through `#_read_book` (a genuine read failure raises `BrokerReadError` → 500, only "no data"/"no record"/"no position" is EMPTY), serialises sweeps per account via `#_get_close_lock`, cancels a stale working SELL and re-prices instead of skipping it (`#_working_sell_orders`), never sells a long past zero (an uncancellable working SELL is subtracted, and the remainder is reported through the `covered` branch), and inspects every close order's HTTP status + orderid so a rejection returns 500 with per-symbol detail instead of `"All Open Positions SquaredOff"`. An unresolvable symbol is a FAILURE, not a silent skip. `#get_open_position` now SUMS every matching row instead of returning the first, and reaches an NFO contract from mStock's NSE-labelled derivative row (`#_row_matches_exchange`). `#cancel_all_orders_api` reads the book through `#_read_book`, so a failed or list-shaped reply can no longer collapse into a false "nothing pending" or a crash. `#_is_success` accepts all three success spellings mStock uses (`True` / `"true"` / `"True"` — the vendor mock book answers `"True"`). `broker/mstock/mapping/transform_data.py#_duration` replaces the hardcoded `duration: "DAY"` in both place and modify, honouring `validity` (`IOC`) and clamping anything unknown to DAY. `place_smartorder_api` invalidates with the caller's `auth` (it used the module-global `AUTH_TOKEN`) and clamps a target on the far side of zero to flat unless `allow_flip` is passed. Tests: `test/test_mstock_squareoff_safeguards.py` (79, fully offline). NOT ported: Flattrade's MARKET→LIMIT MPP rewrite — mStock takes `MARKET`/`STOPLOSS_MARKET` natively, so that would be a behaviour change, not parity. **LOCAL patch to a vendored upstream app — an OpenAlgo upgrade will overwrite it; re-check after any upgrade.** See [[gotchas]].
- **IOC order validity, end to end — the hardcoded `ret: "DAY"` is gone (2026-10-25).** Flattrade (Noren) rejects a raw `MKT` for API orders, so `broker/flattrade/mapping/transform_data.py#transform_data` rewrites every MARKET into a marketable LIMIT priced at the touch. With `ret` hardcoded `DAY`, a remainder that failed to fill at the touch **rested there for the session** — the API answered HTTP 200 + `orderid` while no position existed. `validity` is now a first-class order field: `utils/constants.py` owns `VALIDITY_DAY` / `VALIDITY_IOC` / `VALID_VALIDITY` / `DEFAULT_VALIDITY`; `restx_api/schemas.py#ValiditySchemaMixin` adds the field to `OrderSchema`, `SmartOrderSchema`, `ModifyOrderSchema`, `BasketOrderItemSchema` and `SplitOrderSchema` (default `DAY`, up-cased in a `pre_load` hook because a marshmallow validator cannot mutate the value it checks, `ValidationError` for anything else); `services/place_order_service.py#validate_order_data` enforces the same list for callers that bypass the schema; and `broker/flattrade/mapping/transform_data.py#_retention` reads `data["validity"]` and **clamps** to DAY/IOC, so internal callers (`place_smartorder_api`'s exit branch, `close_all_positions`, `modify_order`) can never emit an invalid `ret`. The MPP rewrite is unaffected — it only touches `prctyp`/`prc` and `ret` is assigned afterwards, pinned by a test. Paper/analyzer mode is unchanged: `services/sandbox_service.py` builds its own order dict and never copies `validity`, so the key is ignored, never rejected. Tests: `test/test_ioc_validity.py` (29). The matching client-side rollback for an IOC entry that is ACCEPTED but fills nothing lives in the Qwantonomous-Engine repo (`ServerController._rollbackUnfilledEntry`); by decision it does NOT reset that app's `StrategyEngine`, so a failed IOC fill waits for the current trend cycle instead of re-entering mid-trend. **This is a LOCAL patch to a vendored upstream app — an OpenAlgo upgrade will overwrite it; re-check after any upgrade.**
- **v1.0.01 zip downloads had no UI and crashed.** `frontend/dist` was git-ignored, so a source archive of any branch whose CI never ran `commit-dist` shipped no build; with `react_bp` unregistered, `serve_react_app`'s bare `(html, 503)` tuple was re-paired by the 404 handler into `((html,503),404)`, raising a TypeError **from inside an error handler** and looping `/error` → 500 → `/error` (ERR_TOO_MANY_REDIRECTS). Fixed by committing `frontend/dist` (`.gitignore` now negates it, `.gitattributes` keeps the bytes verbatim), returning a real `Response` from `blueprints/react_app.py#serve_react_app`, making `app.py#internal_server_error` redirect only when a build exists and it is not already on `/error`, and answering `serve_react_app()` from the `blueprints/auth.py#login` GET fallbacks and `app.py#method_not_allowed_error`. The 31 TypeScript errors that blocked `npm run build` (retired `'strategy'` toast category, unused `event` param) are fixed too. `.env` reads now state `utf-8`. See [[gotchas]].
